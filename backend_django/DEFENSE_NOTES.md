# Короткий текст для защиты

В проекте логика разделена на три простые части:

1. `models.py`  
Здесь описаны таблицы базы данных MySQL как классы Django.

2. `urls.py`  
Здесь указано, какой URL вызывает какую функцию.

3. `views.py`  
Здесь находится основная логика: принять запрос, проверить данные, обратиться к базе и вернуть JSON-ответ фронтенду.

Пароли не хранятся в открытом виде: Django сохраняет их как хеш.  
Для работы с уже существующей базой я подключил Django к MySQL и использовал ORM, чтобы не писать много SQL вручную.

## Совсем короткая версия

Я использовал Django как серверную часть, MySQL как базу данных и оставил совместимый API для фронтенда.  
Модели отвечают за таблицы, `views` за бизнес-логику, а `urls` за маршруты.

## Если спросят, почему Django

- Код стал понятнее и структурированнее.
- Проще объяснять архитектуру.
- Удобно работать с MySQL через ORM.
- Для учебного проекта это читается проще, чем большой файл Express-сервера.
