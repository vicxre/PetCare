# Короткий текст для защиты фронтенда

Во фронтенде я использовал обычный `HTML + CSS + JavaScript`.
Страницы разделены по смыслу: главная, питомцы, вакцинации, отчеты, профиль, вход и регистрация.

Логику я тоже разделил:

1. HTML отвечает за структуру страницы.
2. CSS отвечает за внешний вид.
3. JavaScript отвечает за поведение страницы и запросы к backend.

Чтобы код было легче объяснять, я вынес общие функции в `src/js/app-utils.js`.
Там находятся простые вспомогательные вещи:

- адрес API
- получение пользователя из `localStorage`
- получение `owner_id`
- работа с аватаром
- работа с фотографиями питомцев
- форматирование даты

Поэтому в файлах страниц теперь остается только логика конкретной страницы:

- `main.js` — главная страница
- `pets.js` — список питомцев
- `vacs.js` — вакцинации и календарь
- `report.js` — отчет
- `profile.js` — профиль пользователя
- `navigation.js` — переключение страниц и темы

## Совсем короткая версия

Фронтенд состоит из HTML, CSS и JavaScript.
HTML задает структуру, CSS оформление, JavaScript делает страницу интерактивной и отправляет запросы на Django backend.
Общие функции я вынес в `app-utils.js`, чтобы не дублировать код.

## Если спросят про хранение данных

- пользователь после входа сохраняется в `localStorage`
- оттуда фронтенд берет `user_id`
- с этим `user_id` отправляются запросы к backend

## Если спросят про связь фронта и бэка

Фронтенд отправляет `fetch`-запросы на адреса вида:

- `/api/auth/login`
- `/api/pets`
- `/api/vaccinations`

Backend на Django принимает эти запросы и возвращает JSON.
